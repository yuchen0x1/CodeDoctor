# CodeDoctor 设计规格

日期：2026-11-17  
状态：设计已通过对话确认，等待文档审核  
目标平台：Windows 10/11  
技术路线：Tauri 2 + React/TypeScript + Rust

## 1. 产品目标与边界

CodeDoctor 是一个完全本地运行的 Windows 桌面代码质量体检与治理中心。它读取用户选定的项目，建立只读索引，执行多语言结构分析、规则检测、依赖分析、重复代码分析和可选外部分析器适配，生成可追溯的问题报告、项目健康度评分和可以交给其他 AI 编程工具执行的治理提示词。

本产品不接入 AI 模型，不要求 API Key，不上传源代码，不执行被扫描项目中的脚本，不自动修改或删除用户源代码。所有检测结果必须包含来源、证据、文件位置、覆盖范围和可信度。无法确认的动态行为只标记为疑似问题。

## 2. 总体架构

采用单体桌面应用和可插拔扫描内核，避免引入云服务或常驻多进程基础设施；外部分析器只在单次扫描期间按需启动受控子进程。

### 2.1 Tauri 层

- 负责窗口、文件夹/文件对话框、拖放入口、应用菜单和 Windows 打包。
- 通过受控命令调用 Rust 核心；不直接让前端访问任意文件系统。
- 发送真实扫描事件到前端，支持暂停、取消和错误状态。

### 2.2 React/TypeScript 层

- 页面：总览、项目体检、扫描任务、问题分析、架构分析、注释治理、重复代码、修复提示词、历史报告、设置。
- 负责筛选、排序、搜索、详情展开、代码上下文、图表和导出操作。
- 维护加载、空、成功、错误和取消状态；进度只消费后端事件，不生成假进度。
- 使用深蓝灰背景、青蓝强调色和严重度色阶，提供键盘焦点、清晰标签、可读对比度和减少动画支持。

### 2.3 Rust 核心层

模块边界如下：

- `import`: 文件夹/ZIP 导入、临时目录、路径安全、排除规则。
- `index`: 编码、文件元数据、内容哈希、语言和框架识别。
- `parse`: Tree-sitter 解析器、复合文件分区和能力矩阵。
- `rules`: 内部质量、屎山代码、注释、重复、安全和复杂度规则。
- `analyzers`: Ruff、ESLint、tsc、golangci-lint、Clippy 等本机工具适配器。
- `graph`: 导入、调用、继承、组件引用、耦合度和循环依赖。
- `score`: 七维评分、覆盖率、可信度和技术债务区间。
- `report`: JSON、Markdown、TXT、HTML 报告。
- `prompt`: 全面治理、重点治理和定点修复提示词。
- `history`: SQLite 迁移、扫描快照、指纹对比和历史隔离。

## 3. 扫描数据流

扫描流程固定为：

`导入项目 → 安全解压/建立只读快照 → 文件索引 → 语言与框架识别 → 解析 → 内部规则 → 可选外部分析器 → 依赖/架构图 → 去重与可信度计算 → 评分 → 持久化 → 展示/导出`

`ScanRun` 状态为 `queued`、`running`、`paused`、`canceling`、`completed`、`failed`。后端事件至少包含阶段、当前相对路径、已扫描数、总数、发现数、耗时、暂停/取消状态和错误摘要。

ZIP 导入先解压到应用临时目录，必须规范化每个条目路径，拒绝路径穿越、符号链接逃逸、过多条目、过大展开体积和超大单文件；不得覆盖用户已有文件。目录遍历默认排除 `node_modules`、`.git`、`build`、`dist`、缓存和虚拟环境，并允许用户调整。

每个文件保存相对路径、编码、字节数、内容哈希、语言、解析能力和排除原因。源代码正文不复制进数据库，只按需读取原路径或临时解压目录。

缓存键包含文件内容哈希、规则集版本、分析器版本和扫描配置。未变化文件复用规则结果；依赖图仅重算受影响模块。取消通过共享取消令牌传播到遍历、解析和外部分析器进程，并保存可恢复游标。

## 4. 检测引擎

### 4.1 语言识别与解析能力

语言注册表综合文件扩展名、配置文件、依赖清单和目录特征判断项目技术栈。目标语言包括 Python、JavaScript、TypeScript、Java、C、C++、C#、Go、Rust、PHP、Kotlin、Swift、HTML、CSS、SCSS、Vue、Svelte、SQL、Shell、PowerShell、JSON、YAML、XML。

有成熟 grammar 的语言使用 Tree-sitter，产出函数、类、导入、调用、继承、控制流和注释节点。没有可用 grammar 的语言只启用明确标注的词法或结构规则，结果展示为非 AST 覆盖。Vue、Svelte、HTML、CSS、SCSS 等复合文件按内嵌语言分区解析，同时映射回原文件行号。

### 4.2 规则定义

每条规则包含 `rule_id`、类别、严重度、支持语言、证据类型、可信度策略和修复提示。首版规则组包括：

- 基础质量：命名、无意义变量、重复声明、未使用导入/参数、超长行、魔法数字/字符串、空异常捕获、调试输出、临时代码。
- 屎山代码：超长函数、参数过多、嵌套过深、分支过多、巨型类、文件职责过载、全局状态、跨层调用。
- 注释治理：注释代码、重复解释、显而易见注释、过时 TODO/FIXME、疑似与行为不符注释；版权、公共 API 文档和复杂算法说明不作无用判定。
- 重复代码：归一化 token/行片段生成候选，再进行结构片段比对；最小长度、相似度和跨文件范围可配置。
- 架构：导入边、循环依赖、依赖方向、模块耦合度、目录职责异常、高扇入和高扇出。
- 安全：密钥/密码模式、危险命令执行、路径拼接、SQL 拼接、反序列化、XSS、弱随机数和权限配置，只输出潜在风险、证据和可信度。

所有规则可单独启用、停用和调整阈值。动态导入、反射、插件注册、依赖注入和外部入口无法确认时，结果标记为疑似，不直接生成删除建议。

### 4.3 外部分析器

适配器独立发现、启用、停用和记录版本。优先使用项目已有配置和本机已有可执行文件，不自动联网安装工具。工具缺失、配置错误、超时和非零退出都展示为分析器状态，不伪造“无问题”。统一映射结果时保留原始工具码和输出摘要，并用规则码、位置和规范化消息去重。

## 5. 依赖图与问题模型

图模型至少包含文件/模块节点和导入、调用、继承、组件引用边。支持强连通分量识别循环依赖，计算扇入、扇出和耦合度，并在解析能力不足时标记图的覆盖范围。

问题模型至少包含：问题编号、规则编号、类型、严重度、相对文件路径、起止行列、证据摘要、说明、潜在影响、修复建议、来源分析器、可信度、解析覆盖、状态和关联问题。

问题指纹由项目标识、规则、相对路径、代码范围和规范化证据生成，用于历史扫描识别新增、已解决、持续存在、位置变化和严重度变化。

## 6. 评分、历史与提示词

七个维度及权重固定为：可读性 15、结构 15、可维护性 20、复杂度 15、重复代码 10、架构 15、安全与风险 10。每个维度记录 0–100 分和 `evidence_coverage`。覆盖不足的维度不伪造高分，覆盖率作为证据系数参与总分：`quality_score = Σ(weight × dimension_score × evidence_coverage) / Σ(weight)`；`confidence = Σ(weight × evidence_coverage) / 100`。未评估维度显示未评估；页面同时展示质量分、已评估维度平均分、检测覆盖率和评分可信度。

技术债务只输出有依据的区间和组成因素，不生成未经依据的精确修复小时数。扫描配置、规则版本和分析器版本写入快照，确保历史分数可解释。

项目使用规范化绝对路径和本地项目 UUID 隔离。历史对比使用问题指纹和严重度，输出新增、已解决、持续存在、位置变化和严重度变化，并区分规则变化造成的重新评估。

提示词生成器只读取当前扫描快照。全面治理包含项目画像、技术栈、扫描覆盖、全部问题分组、阶段化治理任务、原始路径/行号/问题编号和验证要求；重点治理仅包含严重、高危、高复杂度、重复、架构和高可信安全问题；定点修复仅包含用户勾选问题及依赖提示。固定包含理解项目、逐项验证、分阶段修复、回归验证、二次扫描六阶段和以下十五项约束：

1. 不破坏现有功能。
2. 不随意删除业务逻辑。
3. 不随意更换技术栈。
4. 不无必要地引入新依赖。
5. 不直接重写整个项目。
6. 修改数据结构时提供兼容方案。
7. 不随意修改公开 API。
8. 保留必要注释和版权声明。
9. 不为降低行数进行无意义重构。
10. 每次修改说明理由。
11. 重要修改提供对应测试。
12. 保留原项目已有功能。
13. 无法确认的代码先保留。
14. 所有修改经过构建和测试验证。
15. 未验证的功能不得宣称完成。

每份提示词保存模式、扫描 ID、问题 ID、时间和模板版本。

## 7. 界面与交互

项目体检页提供文件夹选择和拖拽文件夹/ZIP，显示名称、路径、语言、框架、文件数、代码行数、目录层级、排除目录和扫描配置。扫描页显示真实阶段、当前文件、已扫描数、发现数、耗时、暂停和取消。

结果页提供健康度卡片、严重度统计、问题表、筛选/搜索/排序、代码上下文和架构关系图。问题跳转首先显示相对路径和绝对路径，编辑器协议作为可配置能力。提示词页提供模式切换、问题选择、预览、复制和导出；历史页提供报告对比和增量提示词。

## 8. 存储与导出

SQLite 迁移保存项目、扫描运行、文件索引、问题、分析器运行、架构边、评分快照和提示词历史。导出格式为 JSON、Markdown、TXT 和 HTML。所有导出包含扫描时间、规则/分析器版本、覆盖率和未评估项；路径按项目相对路径展示，避免不同项目结果混淆。

## 9. 验证与测试

`fixtures/` 准备规范代码、超长函数、重复代码、注释污染、未使用导入、深层嵌套、循环依赖、死代码、潜在安全风险和多语言混合项目。

- Rust 单元测试：规则、复杂度、重复检测、依赖图、ZIP 安全、编码、缓存和指纹。
- Rust 集成测试：完整扫描生命周期、暂停/取消、历史差异、评分、报告和提示词证据。
- 前端测试：筛选、详情展开、模式切换、复制/导出、加载/错误/空状态。
- UI 冒烟：使用真实 Tauri 前端构建产物验证窗口、拖放和扫描状态。
- 验收：中文路径、ZIP、行号、无假进度、外部工具缺失状态、离线运行、项目隔离和不执行被扫描脚本。

## 10. Windows 交付与文档

使用 Tauri 2 配置 Windows 安装包、图标、版本、安装目录、卸载信息和日志位置。README 说明用途、支持语言及解析级别、外部分析器边界、开发环境、构建/测试命令、离线和隐私行为。只有真实构建成功才标记安装包可用；没有签名、发布或跨机器安装证据时，不宣称已发布或已验证升级。

建议仓库结构：

```text
src/                    React 页面、组件、状态与样式
src-tauri/src/          Tauri 命令、扫描任务、规则、图、评分、报告、存储
src-tauri/migrations/   SQLite 迁移
fixtures/               多语言与问题样本
tests/                  前端与端到端测试
docs/                   设计、能力矩阵、用户文档
```

## 11. 实施顺序

1. 建立 Tauri/React/Rust 工程、SQLite 迁移和共享类型。
2. 实现项目导入、ZIP 安全、文件索引、语言识别和真实扫描事件。
3. 实现解析能力、内部规则、复杂度、重复代码和依赖图。
4. 实现分析器适配、去重、评分、覆盖率和历史对比。
5. 实现报告、提示词生成、导出和全套页面。
6. 加入测试夹具、集成/UI 测试、README、Windows 构建和安装验证。

每一步保持应用可构建；任何未实现的能力都在 UI 的覆盖矩阵和 README 中明确标注。
