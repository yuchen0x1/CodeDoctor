# 隐私与数据边界

CodeDoctor 的 SQLite 数据库位于 `%APPDATA%\com.codedoctor.desktop\codedoctor.db`。本地数据库包含项目信息、文件路径和摘要、问题证据、评分快照以及生成过的治理任务书。导出的文件保存在用户选择的位置。证据可能含少量代码片段，分享前应确认其内容。

扫描器会读取项目文件来建立索引和解析结果，但不会执行项目脚本、安装项目依赖或上传源代码。ZIP 会先解压到受控临时目录，校验路径和大小后再分析；临时目录在扫描结束后清理。

启用本机 Ruff 后，CodeDoctor 以隔离配置检查所选 Python 文件。扫描保存工具状态与版本。源码预览会核对已保存的文件摘要，限制上下文行数并遮蔽检测到的疑似凭据。文件夹项目中可安全定位的文本文件可用 Windows 记事本打开。ZIP 上下文直接读取经校验的归档成员。

报告导出是明确的本地写入操作，支持 JSON、SARIF、Markdown、TXT 和 HTML。应用不会把报告发送到远程服务。文件路径在报告中以项目相对路径为主，避免不同项目之间混淆；本地 UI 仍可能显示导入项目的绝对路径以帮助定位。

## 凭据遮蔽与既有数据

从 0.2.3 起，源码预览与内置逐文件规则共用敏感行判断，覆盖常见三引号、反引号和 YAML 块值，包括带 TypeScript/Python 类型注解的赋值、Python 字符串前缀，以及括号内普通字符串的隐式或 `+` 拼接。括号续行跟踪引号、注释及实际闭合位置，不把闭合后的普通代码一并隐藏。与识别到的敏感行相交的问题证据在进入缓存和 SQLite 前隐藏；危险执行说明仅显示受限 API 名，不插入可能含字面量的完整调用表达式。规则缓存版本升级，重新扫描不会复用旧脱敏语义的结果。问题仍保留规则、真实位置与建议，最终身份相同的重复发现合并，不会因 ID 冲突令扫描失败。

Markdown 报告对普通字段作 Markdown 转义，多行证据放在长度自适应的独立代码围栏中，避免证据内容被当成原始 HTML 或图片链接解释。TXT 保持原文；JSON 序列化和 SARIF 格式本身不等于内容脱敏。分享或导入到第三方查看器时，仍需检查其网络、HTML 清洗与隐私设置。

这仍是保守启发式，不是完整的秘密检测或数据防泄漏系统，复杂语法、未识别的凭据以及外部分析器消息仍需人工检查。旧历史快照、旧缓存行、已经导出的报告和生成的任务书不会被自动改写或删除；请重新扫描生成当前报告，分享前审阅内容。若曾分享含真实凭据的旧报告，应按自身安全流程撤回并轮换已暴露凭据。

## 已知限制

- 词法级语言不提供函数、类和导入的 AST 指标，评分覆盖率会降低。
- 复合文件的模板和样式只做分区或词法处理，不等同于完整框架语义分析。
- 动态导入、反射、插件注册和依赖注入只能在证据足够时标记，不能证明运行时全部调用关系。
- 外部工具的报告仍需结合业务人工确认，CodeDoctor 不把工具告警直接当作确定漏洞。
