# 隐私与数据边界

CodeDoctor 的 SQLite 数据库位于 `%APPDATA%\com.codedoctor.desktop\codedoctor.db`。本地数据库包含项目信息、文件路径和摘要、问题证据、评分快照以及生成过的治理任务书。导出的文件保存在用户选择的位置。证据可能含少量代码片段，分享前应确认其内容。

扫描器会读取项目文件来建立索引和解析结果，但不会执行项目脚本、安装项目依赖或上传源代码。ZIP 会先解压到受控临时目录，校验路径和大小后再分析；临时目录在扫描结束后清理。

启用本机 Ruff 后，CodeDoctor 以隔离配置检查所选 Python 文件。扫描保存工具状态与版本。源码预览会核对已保存的文件摘要，限制上下文行数并遮蔽检测到的疑似凭据。文件夹项目中可安全定位的文本文件可用 Windows 记事本打开。ZIP 上下文直接读取经校验的归档成员。

报告导出是明确的本地写入操作，支持 JSON、Markdown、TXT 和 HTML。应用不会把报告发送到远程服务。文件路径在报告中以项目相对路径为主，避免不同项目之间混淆；本地 UI 仍可能显示导入项目的绝对路径以帮助定位。

## 已知限制

- 词法级语言不提供函数、类和导入的 AST 指标，评分覆盖率会降低。
- 复合文件的模板和样式只做分区或词法处理，不等同于完整框架语义分析。
- 动态导入、反射、插件注册和依赖注入只能在证据足够时标记，不能证明运行时全部调用关系。
- 外部工具的报告仍需结合业务人工确认，CodeDoctor 不把工具告警直接当作确定漏洞。
